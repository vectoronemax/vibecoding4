# 平台知识图谱（kg-cockpit）

平台的知识图谱板块。和其它大屏一样：纯前端、本地 ECharts、`build_data.py` 产出 `data.js`、网页只读 `data.js`。

- **自带一张图谱**：控规质检规则图谱，从 `资料/质检智能体/规则库_参考.yaml` 逐字段整理，不用大模型抽取，每条关系都能回到 YAML 的某个字段。
- **能接 Yuxi**：数据结构对齐 [Yuxi](https://github.com/xerrors/Yuxi) 的 `/api/graph/subgraph`，Yuxi 知识库用大模型抽出来的图谱，一条命令拉进来，网页不用改。

## 怎么跑

```bash
python3 apps/kg-cockpit/build_data.py
```

```bash
python3 -m http.server 8000
```

浏览器打开 `http://localhost:8000/apps/kg-cockpit/`。

直达链接：`#g=图谱id&n=实体名或编号&v=tree`，例如 `apps/kg-cockpit/#g=qc-rules&n=Q07`。别的大屏（比如质检结果页）可以用它直接跳到某条规则。

## 页面

| 视图 | 能做什么 |
|---|---|
| 图谱 | 搜索实体（名称、编号、属性文字都搜）；点节点看属性和 1 跳 / 2 跳邻域，视图自动移到邻域；点类型隐藏 / 显示；左下角是 `build_data.py` 的核对结果 |
| 导图 | 规则库 → 类别 → 规则 → 依据 / 用词 / 判定 / 适用用地，点 ▸ 展开 |

对应 Yuxi 的三项图谱功能：按关键词搜索实体、点节点看属性并高亮关联子图、知识导图。

## 质检规则图谱是怎么来的

| 实体 | 个数 | 出处 |
|---|---|---|
| 规则 | 21 | YAML `规则`（Q01–Q21），属性带原文、口径、参数、检查函数 |
| 规则类别 | 9 | 规则的 `类别` 字段 |
| 依据文件 | 5 | YAML `依据文件` 4 份 + 「课程口径」 |
| 条文 | 28 | 从 `依据` 字段切出来的条文号，如 `准则2016 4.3.2`；能在条文摘录里找到的附上摘录原文 |
| 用词 / 严重度 | 8 / 4 | YAML `用词与严重度`（准则附录五） |
| 用地 | 30 | `适用`、`口径` 里提到的用地代码，归到中类（Rs4 → Rs），原文写法记在关系上；名称只取自条文摘录，摘录没写的留空 |
| 明确不查 | 3 | YAML `不适用` |

关系：依据、出自、参照、属于、用词、对应、判定、适用于、口径涉及、归属大类、口径引用（如 Q20 无效则跳过 Q12、Q18、Q19）。

**验收数字**（写 `run_all.py` 断言时用）：节点 **108**、关系 **213**；规则 **21**；条文 **28**，其中摘录收录 **26**（表3-1、7.4.2 摘录里没有）；规则「原文」与摘录逐字一致 **15** 条、近似 **1** 条（Q07，摘录多了「（见附录二）」）、原文为空 **5** 条（课程口径）；用词 → 严重度与规则自己写的严重度一致 **20** 条（Q05 用词是「定义」，附录五里没有，无法核对）；孤立节点 **0**。

依据认不出文件、条文号格式不对、用地代码不在字典里，脚本都会列出来并中止，不静默丢弃。坐标在脚本里用固定随机种子算好，重跑结果一致。

## 与 Yuxi 怎么结合

### 两边各是什么

| | 本平台 | Yuxi |
|---|---|---|
| 形态 | 静态大屏，一个文件夹，无后端 | 多服务部署：FastAPI、PostgreSQL、Redis、MinIO、Milvus、Neo4j、LangGraph、沙盒 |
| 知识从哪来 | 人整理、人审定的数据和规则 | 上传文档 → 解析分块 → 向量索引 → 大模型抽实体关系写进 Neo4j |
| 擅长 | 口径可核对、可以公开发布 | 文档问答（RAG）、知识图谱、多智能体、权限管理 |

不建议把 Yuxi 塞进平台：平台部署是静态托管，放不进 Neo4j 和 Milvus；浏览器直接请求 Yuxi 会跨域，API Key 也会暴露在页面源码里。合适的做法是**两边各自部署，在数据层对接**。

### 三层结合

1. **数据格式对齐（已完成）**。`data.js` 里每张图谱的节点和关系字段，与 Yuxi `/api/graph/subgraph` 返回的 `{nodes, edges}` 一一对应。Yuxi 的图谱经 `fetch_yuxi.py` 拉进来，和质检规则图谱并列显示：

   ```bash
   export YUXI_BASE_URL=http://localhost:5050
   ```

   ```bash
   export YUXI_API_KEY=yxkey_...
   ```

   ```bash
   python3 apps/kg-cockpit/fetch_yuxi.py --list
   ```

   ```bash
   python3 apps/kg-cockpit/fetch_yuxi.py --kb-id <知识库ID> --max-nodes 300
   ```

   ```bash
   python3 apps/kg-cockpit/build_data.py
   ```

   Key 在 Yuxi「设置 → API Keys」创建，权限选 **full**，所属账号要是**管理员**（图谱接口要求管理员，knowledge / agents 权限的 Key 访问不了）。Key 只从环境变量读，不落盘、不打印。

2. **知识库和图谱构建放在 Yuxi**。把平台的文字资料建成 Yuxi 的 Milvus 知识库：`资料/质检智能体/上海控规质检_条文摘录.md`、`data/qc/教学单元_说明书.md` 以及其它口径说明。在知识库详情页选抽取模型并提交图谱构建（Yuxi 不会在解析后自动构建），再用上面的命令拉回来。

   这样平台上就有两张可以对照的图：**人审定的规则图谱**，和**大模型从同一批条文里抽出来的图谱**。拿前者核对后者，比如大模型有没有把「准则2016 4.3.2」和「轨道交通站点 300 米」连起来、有没有把「宜」当成「应」，正好符合本课程「AI 的产出要能被验证」的要求。

3. **智能体放在 Yuxi，平台负责展示**。质检智能体可以在 Yuxi 里配置：知识库做检索，`qc_tools.py` 的检查函数做成工具或 Skill，在沙盒里执行。规则库仍然是人审定的只读数据，智能体只能「选规则、调工具、解释结果」，不能改数值。智能体回答里引用到规则时，链接到 `apps/kg-cockpit/#g=qc-rules&n=Q07`，回到平台看依据条文和关联规则。

### 注意

- 子图受 `--max-nodes` 截断（Yuxi 上限 1000），节点数到上限时核对栏会给 ⚠，不代表知识库全部实体。
- 大模型抽取的实体关系**未经人工审定**，页脚和说明里都写明了。
- `apps/kg-cockpit/yuxi/` 已写进 `.gitignore`，但重跑 `build_data.py` 后，`data.js` 里会包含拉下来的图谱。push 之前按 `资料/上线前体检清单.md` 检查：知识库里的期刊论文这类内容**不放**进公开仓库。
- 接口对照的是 Yuxi 源码 `backend/yuxi/api/routers/knowledge/graphs.py` 和 `modules/knowledge/graphs/service.py`（2026-11-03 版本）。`fetch_yuxi.py` 用按同样结构返回的模拟接口测过，还没有连真实的 Yuxi 实例跑过；Yuxi 升级后接口变了，以它的 Swagger 页面为准。

## 文件

| 文件 | 作用 |
|---|---|
| `build_data.py` | 读规则库 YAML、条文摘录和 `yuxi/*.json`，写 `data.js` |
| `fetch_yuxi.py` | 从 Yuxi 拉子图，存到 `yuxi/<知识库ID>.json`（只用标准库） |
| `data.js` | `window.KG_DATA`，由脚本生成，勿手改 |
| `index.html` | 页面，只读 `data.js` 和 `../../assets/echarts.min.js` |
