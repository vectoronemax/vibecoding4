# 带教智能体 · 讲师手册

> 这份手册讲**怎么打包、怎么自测、怎么核对答案键、怎么上课**。设计思路见 `00_设计方案.md`。
> 本目录（`资料/带教智能体/`）是讲师目录：**不要整个发给学员**，发打包出来的 `dist/质检智能体工坊.zip`。

## 二、打包

```bash
python3 -m pip install pyyaml shapely pyproj
```

```bash
python3 资料/带教智能体/打包.py --zip
```

半天版（L1 只做 Q03、Q08、Q15；L5 只做 R1）：

```bash
python3 资料/带教智能体/打包.py --压缩 --zip
```

输出 `dist/质检智能体工坊/` 和 `dist/质检智能体工坊.zip`（约 170 KB，74 个文件；`dist/` 不进 git）。打包时会**用参考实现核对三件事，任何一件对不上就停**：

1. 21 条规则的 32 份小样本，参考实现全部对上期望；
2. 教学单元（26 条）、变体单元（24 条）的错误 / 待确认，和 `出题/答案键.yaml` 一模一样；
3. 红队 R1、R3 的结果符合预期。

对不上时，**先查为什么，不要改答案键去迁就实现**——和「四天验收数字」是同一条规矩。

## 三、自测（改了任何东西都跑一遍，约 1 分钟）

```bash
python3 资料/带教智能体/自测.py
```

它打一个包到临时目录，扮演学员从 L0 走到 L6，每关先做反向测试（该拦的要拦住）再做正向测试，完整版 64 项（`--压缩` 测半天版，63 项）。覆盖：

- 钩子拦下对讲师文件的写入、放行学员作品；登记进只读清单的文件也被拦下；
- L0「不做」少于 3 条、L1 原文被改写 / 「宜」判成错误 / 没签字，都过不了；
- L2：阈值写死、代码前缀写死、用属性面积判广场、`upper()` 洗掉大小写、缺值当通过、参数键缺失，都被小样本或改阈值测试拦住；合并后 21 条规则全部对上小样本；
- L3：报告漏写一条错误、出现工具没给的编号、claims.json 原文是改写的，都过不了；
- L4：先看结果后定合格线过不了；改合格线不写理由被拒；评测结果教学单元 26/26、变体单元 24/24；
- L5：报告没有「需人工核实的声明」过不了；
- 讲师文件被改一个字节，验收立刻失败；恢复后恢复。
- 班级进度汇总：3 份进度文件 + 1 个不相干的文件，汇总出总览、卡点；两种问法的 Q08 归到同一道题下。

自测里的 `/qc` 是「模拟 qc」（按模板写报告），验证的是验收脚本和工具链。**真模型要另外试跑**（第五节）。

## 四、核对答案键（发包之前必须做）

`出题/答案键.yaml` 现在是**由参考实现生成、待讲师核对**的状态，打包时会提示「答案键还没经讲师核对签字」。核对办法：

1. 打开 `出题/答案键_核对表.md`：50 条每条都列了「工具算出的值」「相关地块属性」「依据」，认可就把 `[ ]` 改成 `[x]`。重新打包时，内容没变的条目会保留你打的勾，内容变了的会清掉，提醒你重看；打包输出会显示「核对表已勾 x / 50 条」。变体单元每处改动的原因写在 `出题/变体与红队.py` 里，一处一行注释。
2. 有不同意见的地方：先改**口径**（`资料/质检智能体/规则库_参考.yaml`）或**数据**，重新打包，让参考实现和答案键对上；不要单改答案键。
3. 没问题就在 `出题/答案键.yaml` 里把「审定人」签上、「状态」改成「已核对」。

教学单元 26 条的分布：Q01 1 · Q02 2 · Q03 2 · Q04 1 · Q05 2 · Q06 1 · Q07 2 · Q08 1 · Q09 2 · Q11 1 · Q12 1 · Q13 1 · Q14 1（待确认）· Q15 1 · Q17 1 · Q18 2 · Q19 1 · Q20 1 · Q21 2。另有 2 条提示（Q10、Q16）、3 条无法检查（Q07 街坊 22、06-02 的 Q18/Q19），不计入评测。

几个讲课时值得点出来的「陷阱」（参考实现都按口径处理了）：

| 陷阱 | 在哪 | 正确处理 |
|---|---|---|
| 单块超标、街坊平均不超 | 20-01 容积率 2.6 | 开发强度按街坊平均判，不报 |
| 站点 300 米内，但站是在建 | 小样本 Q07 的街坊 04（教学单元里街坊 12 也靠近在建的虹湾路，但它是 II 级、没有特定强度，结果不受影响） | 在建站不算，仍按基本强度 |
| 站点 300 米内且是运营站 | 街坊 18（2.4） | 用特定强度 ≤ 2.5，不报 |
| 改建住宅绿地率 26% | 07-04 | 改建门槛 25%，不报 |
| 幼托 Rs6 南北向只有 38 米 | 05-03 | Q12 只管 Rs1–Rs5，不报 |
| 广场超 2 公顷不计入小型公共空间 | 15-02 | Q14 分子里剔除 |
| 变体单元：正好 100 米的住宅 | 20-02 | 按参考口径（> 100）不报；学员口径不同，L4 记进「口径差异」 |
| 变体单元：超 2 公顷但备注「特定功能」 | 22-01 | 只给提示 |

## 五、试跑（用真模型走一遍）

自测之外，发包之前至少用**学员会用的后台**（Claude，或 CC Switch 接的 DeepSeek）走一遍关键环节。打包后在学员包目录里：

```bash
cd dist/质检智能体工坊
```


进去以后输入 `/coach`，按第八节（设计方案）的三种学员各扮一遍。只想单测质检智能体，可以用无交互模式（先把存档点 L2/L3 放好，规则库签上名）：

```bash
claude -p "/qc data/qc qc_agent/报告" --allowedTools "Bash(python3:*)" Read Write Glob Grep
```

| 试跑 | 结果 |
|---|---|

## 六、上课

**课前**
- 学员已有 Python 3.9+ 和 Claude Code；课前装好 `pyyaml shapely pyproj`。
- 发 `质检智能体工坊.zip`，解压后在**解压出来的那一层**打开 Claude Code（有 `CLAUDE.md` 的那层），输入 `/coach`。

**课上三个集体时间点**（见设计方案第六节）
1. 开场：用存档点跑一遍成品（`/qc data/qc qc_agent/报告`），再演示 R1 注入。
2. 中场：让学员把项目根目录的 `学习进度.json` 发到群里（或者共享文件夹），讲师下载到同一个文件夹，跑一下汇总（文件名重复没关系，按文件内容认人）：
   ```bash
   python3 资料/带教智能体/汇总进度.py <放进度文件的文件夹> --out 班级进度.md
   ```
   打开 `班级进度.md`：「卡在哪」看哪一关最卡、卡在哪一项；「口径分歧」里同一道决策题全班的回答排在一起，挑 Q04 的「一般」、Q08 的 100 米讲。
3. 收尾：再汇总一次，看「合格线与评测」：比 L4 的检出率和误报，不比谁先做完；演示 R2；一起拆解带教智能体。

只想快速看谁在哪一关，也可以让学员跑 `python3 带教/progress.py card` 把一行进度码贴到群里。

**学员卡住时**：带教智能体有四级提示，第四级才给存档点；学员的原文件会备份到 `qc_agent/_备份/`。

## 七、常见问题

| 现象 | 原因 / 处理 |
|---|---|
| 输入 `/qc` 说没有这个命令 | 不在学员包根目录开的会话，或者 SKILL.md 刚写好还没开新会话 |
| 验收说「讲师文件被改过」 | 从 zip 里把那个文件拷回原处；钩子拦不住 Bash 里的 sed，所以有这道哈希校验 |
| `python3` 找不到（Windows） | 命令里换成 `python`；钩子命令会依次试 `python3`、`python`、`py`，挑第一个真能运行的 |
| Windows 上钩子没生效 | Claude Code 在 Windows 上用 Git Bash 跑钩子；没装 Git Bash 时改用 PowerShell，这条 bash 写法会失效（写入不再被拦，但验收的哈希校验仍然有效）。让学员装 Git for Windows |
| 学员把 `qc_agent/qc_tools.py` 改坏了 | 从 `存档点/L2/qc_tools.py` 拷回来（框架和参考实现一起放在那里） |
| L4 有漏报，但学员说是口径不同 | 对照决策记录，让学员写进评测记录的「口径差异」；合格线是学员自己定的 |
| L2 合并后某条小样本没对上 | 多半是学员自己的函数（同名优先）和参考口径不同；看验收输出的对象，对照 `带教/小样本/Qxx.json` |

## 八、改了东西以后

| 改了什么 | 要做什么 |
|---|---|
| 教案 `关卡.yaml`、带教 SKILL.md、验收脚本 | 重新打包 + 自测 |
| 参考规则库的口径或参数 | 重新打包：参考实现结果变了会停下，核对后同步改答案键并重新签字 |
| `data/qc` 教学单元 | 同上；变体单元从教学单元生成，`出题/变体与红队.py` 里按地块编号改的地方可能要跟着调 |
| 新增规则 | 规则库加一条 + `参考检查.py` 加函数 + `出题/小样本.py` 加小样本，再打包 |

## 九、已知限制

- 答案键哈希防偷看、不防破解（组合只有一千多种）。L2 合并后学员能看到参考实现在教学单元上的全部结果，所以 L4 真正考泛化的是**变体单元**。
- 钩子只拦 Edit / Write 类工具，拦不住 Bash；靠验收脚本的哈希校验兜底。Windows 上还依赖 Git Bash。
- 班级进度汇总要学员手动交 `学习进度.json`，不是实时的；「口径分歧」按问题文字的相似度归类，对不上的放在「其他」里。
- 质检规则的口径是课程口径（见规则库说明），正式质检以主管部门口径和现行文本为准。
