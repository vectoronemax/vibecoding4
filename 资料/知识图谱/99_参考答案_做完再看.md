# 参考答案 · 埋错版规则库的 6 处错

> 实操 4（第 11 句）做完再看。下面的「怎么发现」是用参考实现 `apps/kg-cockpit/` 跑出来的；
> 你自己写的核对不一样，发现的方式也会不一样，**以「错在哪」为准**。

```bash
python3 apps/kg-cockpit/build_data.py --rules 资料/知识图谱/规则库_埋错版.yaml
```

|---|---|---|---|

**脚本和核对栏拦下 4 处，另外 2 处只有人看得出来。** 这正是本专题想让学员带走的一句话：自动核对管得了格式，管不了意思。

## 逐条

**1 · Q16 依据文件名拼错（准侧2016）**
第一次跑就中止：

```
✗ 规则库有字段解析不了，已中止，未写出 data.js
  - Q16 依据「准侧2016 8.3.1」认不出文件名
```

如果脚本没有「认不出就中止」，会发生两种情况之一：多出一个叫「准侧2016」的依据文件；或者 Q16 悄悄失去依据，图上没有任何异常。这就是红线第 4 条「解析不了的不许跳过」。

**2 · Q18 用词抄错（应 → 宜）**
修好第 1 处后再跑，核对栏：

```
✗ 用词→严重度 与规则写的严重度一致：19  Q18 用词→{'提示'}，规则写 {'错误'}
```

「宜」对应「提示」，规则却判「错误」，两者必有一错。回原文判断：准则 3.2.3「地块用地面积**应**按照地块边界的水平投影进行量算」，所以是用词抄错，严重度没错。
（核对只能告诉你「这两个字段对不上」，判断哪个错，要回原文。）

**3 · Q15 原文里的数字改了（2 公顷 → 3 公顷）**
核对栏只给了个 ⚠：

```
⚠ 规则「原文」与摘录逐字一致：13  …；近似一致 2 条：Q07、Q15；…
```

点开 Q15，详情里写着「近似一致（相似度 0.98）」，摘录差异是「原文「3」↔ 摘录「2」」。同一张卡片上还有两个旁证：名称是「单个广场不得大于 **2** 公顷」，口径是「几何面积 > **20,000** 平方米」。
**相似度 0.98，错的却是最要命的阈值。** 「近似一致」必须由人看差异，这是红线第 5 条。
对照一下 Q07，它也是「近似」，差的是摘录多了个「（见附录二）」，不影响意思，可以接受。

**4 · Q12 条文号写错（7.5.3 → 7.5.8）**
核对栏两处有反应：「条文节点在摘录里找到原文 25/28，未收录：…准则2016 7.5.8…」；Q12 的「摘录核对」是「摘录未收录对应条文」。
「摘录里没有」本身不一定是错（参考版里的表3-1、7.4.2 也没收录）。要在摘录里搜 Q12 原文里的关键词「南北向」，就会发现它其实在 7.5.3 下面。

**5 · Q13 类别归错（公共服务设施 → 公共空间）**
没有任何自动核对能发现。看导图：「公共空间」下面多了一个「Q13 需独立用地的社区设施」（派出所、社区卫生服务中心）；「公共服务设施」只剩 Q11、Q12。
在关系图谱里看更明显：Q13 依据的 7.4.2、表7-3 属于准则第 7 章（公共服务设施），和其它几条公共空间规则依据的 5.5.x、8.3.1 不是一回事。

**6 · Q08 适用代码和名称对不上（Rr\* → Rs\*）**
同样没有自动核对。点 Q08「不得建设超高层住宅」：适用于 → **Rs 基础教育**。规则管的是住宅，却连到了学校用地。
详情里「适用」一栏写的是「住宅组团用地（Rs\*）」，文字和代码自相矛盾，只有懂业务的人一眼能看出来。

## 两处「看起来像错、其实不是」

| 规则 | 核对栏 | 为什么不算错 |
|---|---|---|
| Q07 | ⚠ 近似一致（0.86），摘录多「见附录二」 | 规则抄原文时省略了括号注，意思没变 |
| Q05 | 用词「定义」无法核对 | 3.4.1 是定义条款，本来就没有「应 / 宜」，严重度由口径定 |

能把这两处和真正的错区分开，比找全 6 处更重要。
