## 二、为什么要做

专题 E 的规则库是一张「表」：一条规则一段 YAML。规则和条文、用词、用地之间的关系，都藏在字段的文字里。
想回答下面这些问题，只能一条条翻：

- 哪几条规则依据准则 4.3.2？
- 哪些规则管学校用地（Rs）？
- 有没有规则，用词是「宜」，严重度却写了「错误」？
- 规则里抄的「原文」，和条文原文一字不差吗？

整理成知识图谱（**实体 + 关系 + 属性**）之后，前两个问题点一下就能看到，后两个只要数一数、对一对。
**图谱不只是好看，它还是规则库的体检工具。** 实操 4 就用它，从一份埋了错的规则库里把错找出来。

## 三、和 Yuxi 是什么关系

[Yuxi](https://github.com/xerrors/Yuxi)（MIT 协议）是一个可私有部署的知识库加智能体平台：上传文档，**由大模型抽取实体和关系**，写进 Neo4j 图数据库，供检索和浏览。

| | 本专题的图谱 | Yuxi 的图谱 |
|---|---|---|
| 实体和关系谁定 | **人定**（schema 写在提示词里） | 大模型自己抽 |
| 每条关系的出处 | 规则库 YAML 的某个字段 | 文档里的某个片段（chunk） |
| 能不能当依据 | 能，规则库由人审定签字 | 不能直接当，要人核对 |
| 部署 | 一个文件夹 | Docker：PostgreSQL、Milvus、Neo4j、MinIO、Redis… |

两者能接上：本专题 `data.js` 的结构对齐 Yuxi 的图谱接口（`/api/graph/subgraph`），
Yuxi 抽出来的图谱用 `apps/kg-cockpit/fetch_yuxi.py` 一条命令就能拉进大屏，和人审定的图谱并排对照。这一段由讲师现场演示（第 12 句），学员不用装 Yuxi。

## 六、🔴 口径红线（违反即为错，不是风格问题）

1. **每条关系都要能回到规则库的某个字段。** 从哪个字段都找不到出处的关系，不要。这是本专题图谱和大模型抽取图谱的根本区别。
2. **schema 由人定。** 有哪几类实体、哪几种关系、「依据」字段怎么切，都写在提示词里，不让 AI 猜。
3. **名称不许编。** 用地代码的名称只取自条文摘录「表3-2 用到的代码」；摘录里没写的（S6、S9、T、M1）留空。
4. **解析不了的不许跳过。** 认不出的文件名、条文号、用地代码，要列出来并中止，不能静默丢掉。
5. **「近似一致」不等于「一致」。** 数字抄错了，相似度照样有 0.98，必须由人看差异。
6. **大模型抽取的图谱要标明「未经人工审定」**，不能拿来当质检依据；子图被截断时，不能据此说「知识库里没有某个实体」。

## 七、验收数字

用参考规则库（`规则库_参考.yaml`）跑，每一步累计应该是：

| 做到第几句 | 实体 | 关系 | 新增 |
|---|---|---|---|
| 第 3 句 | 30 | 21 | 规则 21、规则类别 9；属于 21 |
| 第 4 句 | 66 | 87 | 依据文件 5（4 份 + 课程口径）、条文 28、明确不查 3；依据 34、出自 31、参照 1 |
| 第 5 句 | 78 | 140 | 用词 8、严重度 4；对应 8、用词 20、判定 25 |
| 第 6 句 | **108** | **213** | 用地 30；适用于 25、口径涉及 27、归属大类 18、口径引用 3 |

第 7 句的核对结果：

- 条文在摘录里找到原文：**26 / 28**（表3-1、7.4.2 摘录里没有）
- 规则原文与摘录逐字一致：**15** 条；近似 **1** 条（Q07，摘录多了「（见附录二）」）；原文为空 **5** 条（课程口径）
- 用词 → 严重度一致：**20** 条（Q05 的用词是「定义」，附录五里没有，无法核对）
- 孤立节点：**0**

用的是自己审定过的规则库时，数字会不一样。那就用同样的方法自己算一遍，再和参考版比，说得清差在哪就算过。

## 八、环境

```bash
python3 -m pip install pyyaml numpy
```

本地预览要起 http 服务，双击 `index.html` 读不到 `data.js`：

```bash
python3 -m http.server 8000
```

浏览器打开 `http://localhost:8000/apps/kg-cockpit/`。
