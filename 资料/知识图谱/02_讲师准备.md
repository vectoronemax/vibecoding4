## 二、Yuxi 演示怎么准备（约 1–2 小时，课前做完）

Yuxi 是多服务应用（PostgreSQL、Redis、MinIO、Milvus、Neo4j…），**不要让学员现场装**，讲师一台机器演示即可。
以下按 Yuxi 官方「快速开始」整理（2026-11 版，固定版本 `v0.8.0.beta7`）；以官方文档为准：<https://xerrors.github.io/Yuxi/intro/quick-start>。

1. 准备 Git、Docker、Docker Compose v2；一个模型供应商的 Key（初始化脚本默认要 `SILICONFLOW_API_KEY`，其它供应商登录后再配）。
2. 下载并初始化：

   ```bash
   git clone --branch v0.8.0.beta7 --depth 1 https://github.com/xerrors/Yuxi.git
   ```

   ```bash
   cd Yuxi && ./scripts/init.sh
   ```

3. 启动（Container 沙盒）并等就绪：

   ```bash
   docker compose --profile container up --build -d
   ```

   ```bash
   curl --fail http://localhost:5050/api/system/ready
   ```

4. 打开 <http://localhost:5173>，创建超级管理员；在「智能体 → 模型供应商」配置模型。
5. 新建一个 **Milvus** 知识库（图谱只支持 Milvus 知识库），上传 `资料/质检智能体/上海控规质检_条文摘录.md`，等解析和向量索引完成。
6. 在知识库详情页配置图谱抽取模型，**提交图谱构建**（Yuxi 不会在解析完自动构建），等后台任务完成。
7. 「设置 → API Keys」建一个 Key：权限选 **full**，账号必须是**管理员**（图谱接口要求管理员；knowledge / agents 权限的 Key 访问不了 `/api/graph`）。
8. 在本平台项目里试拉一次：

   ```bash
   export YUXI_BASE_URL=http://localhost:5050
   ```

   ```bash
   export YUXI_API_KEY=yxkey_...
   ```

   ```bash
   python3 apps/kg-cockpit/fetch_yuxi.py --list
   ```

   ```bash
   python3 apps/kg-cockpit/fetch_yuxi.py --kb-id <知识库ID> --max-nodes 300
   ```

   ```bash
   python3 apps/kg-cockpit/build_data.py
   ```

   刷新页面，右上角「图谱」里应出现「Yuxi · 知识库名」。

**注意**：`fetch_yuxi.py` 是对着 Yuxi 源码里的接口（`backend/yuxi/api/routers/knowledge/graphs.py`）写的，用结构相同的模拟接口测过，**还没有连真实实例跑过**。第一次演示前务必按第 8 步实跑一遍；Yuxi 升级后接口有变化，以它的 Swagger 页面为准。

**演示时看什么**（第 12 句的 💡）：
- 搜「4.3.2」或「300 米」：Yuxi 图里，轨道站点 300 米和特定强度有没有连起来；
- 搜「宜」「不得」：有没有把用词的严格程度抽错；
- 看实体类型分布：有没有原文里根本没有的实体。
- 结尾一句：**大模型抽取的图谱是线索，不是依据。**

**课堂网络或 Docker 出问题时的退路**：提前把第 8 步拉下来的 `apps/kg-cockpit/yuxi/<知识库ID>.json` 存一份，现场只跑 `build_data.py`。这个文件已经被 `.gitignore` 排除，不会被推到公开仓库。
