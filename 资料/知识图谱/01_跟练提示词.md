# 跟练提示词 · 12 句做出平台知识图谱

> **怎么用**：一句一句念给 Claude Code，做出来对一下验收数字，再念下一句。
> 每句下面的 ✅ 是验收标准，💡 是**讲师现场讲的话**，学员不用照念。
> 用自己审定过的规则库时，把提示词里的 `规则库_参考.yaml` 换成你的文件；验收数字会不一样，说得清差在哪就算过。

| 阶段 | 句号 | 做出什么 |
|---|---|---|
| A · 认识规则库 | 1–2 | 摸清字段；定下图谱的实体和关系 |
| B · 数据层（实操 1） | 3–7 | 108 个实体、213 条关系，加一份规则库体检报告 |
| C · 画出来（实操 2、3） | 8–10 | 关系图谱、邻域和详情、知识导图、直达链接 |
| D · 图谱体检（实操 4） | 11 | 从埋错版规则库里找出 6 处错 |
| E · 接 Yuxi（讲师演示） | 12 | 人审定的图谱和大模型抽取的图谱并排对照 |

---

# A · 认识规则库（1–2）

## 1 · 先认识规则库，别急着写

```
我要把专题 E 的质检规则库整理成知识图谱。规则库在 资料/质检智能体/规则库_参考.yaml。
先别写任何代码。帮我数一数：有几条规则、几个类别、几份依据文件；
再看「依据」「用词」「严重度」「适用」这四个字段，各有哪几种写法，每个字段举一个最复杂的例子。
```
✅ 21 条规则、9 个类别、4 份依据文件（另有「课程口径」）。最复杂的写法：依据看 Q01（括号里还套着分号）、Q17（两份文件）、Q21（只有文件、没有条文号）；用词看 Q04、Q13；严重度看 Q14（有「待确认」）。

💡 先摸清家底再动手，全课第一条规矩。这一步要让学员**亲眼看到** Q01 括号里那个分号，下一句才知道为什么要人定口径。

## 2 · 定 schema：实体和关系由人定

```
图谱的实体和关系我来定：
实体 8 类：规则、规则类别、依据文件、条文、用词、严重度、用地、明确不查；
关系：规则 -属于→ 规则类别；规则 -依据→ 条文（或直接 → 依据文件）；条文 -出自→ 依据文件；
规则 -用词→ 用词；用词 -对应→ 严重度；规则 -判定→ 严重度；规则 -适用于 / 口径涉及→ 用地；
用地中类 -归属大类→ 用地大类；规则 -口径引用→ 规则；明确不查 -出自→ 依据文件。
先别写代码，把这张表复述给我：每种关系从 YAML 的哪个字段来。
从哪个字段都找不到出处的关系，不要。
```
✅ AI 复述出 11 种关系，每种都对应到一个字段（依据、用词、严重度、适用、口径、用词与严重度表、不适用），没有凭空多出来的关系。

💡 **这是和 Yuxi 最大的不同。** Yuxi 让大模型自己决定抽什么；我们先由人定 schema，每条关系都能回到字段。代价是覆盖面窄，好处是每一条都能当依据。

# B · 数据层（3–7）· 实操 1

## 3 · 先做规则和类别

```
写 apps/kg-cockpit/build_data.py，读规则库，输出 apps/kg-cockpit/data.js（window.KG_DATA）。
节点和关系用数组下标引用：节点 {t: 类型下标, n: 名称, s: 短标签, p: 属性}，关系 [起点, 终点, 关系下标, 属性]。
先只做两类实体：规则（名称写成「Q07 街坊开发强度…」，短标签 Q07，属性带上原文、口径、参数、检查函数）和规则类别。
跑完打印各类实体和各种关系的个数。
```
✅ 实体 30（规则 21、规则类别 9），关系 21（属于 21）。

💡 用下标而不是重复写字符串，和其它大屏的 `data.js` 一个思路：换数据只重跑脚本，网页一行不改。

## 4 · 依据 → 条文 → 文件（口径要人定）

```
加上依据。「依据」字段按我说的切：
① 先按括号外的「；」切成几段——Q01 括号里那个「；」不算；
② 每段开头是文件简称（准则2016、成果规范2020、技术规定、绿化审核、课程口径），后面是用「、」隔开的条文号；
③ 括号里的是注，不是条文号；注里提到别的文件，记一条「参照」关系；
④ 只有文件、没有条文号的（如 Q21 的成果规范2020），规则直接连到文件。
认不出的文件名、不像条文号的写法，列出来并停止，不要跳过。
再把规则库最后「不适用」的 3 条，加成「明确不查」实体，连到它所属的文件。
```
✅ 累计实体 66、关系 87：依据文件 5、条文 28、明确不查 3；依据 34、出自 31、参照 1（Q01 → 成果规范2020）。

💡 「怎么切」就是口径。让 AI 自己猜，它很可能把 Q01 括号里的分号也切开，切出一段「成果规范2020 的普适图则指标表）」，当成 Q01 的第二条依据——**不报错，图上也看不出来**，只有依据 34、参照 1 这两个数对不上。

## 5 · 用词 → 严重度

```
加上用词和严重度。用词和严重度的对应来自规则库开头的「用词与严重度」表（准则附录五）。
每条规则：「用词」字段里出现哪个词就连哪个，按最长匹配——「不宜」不能拆成「宜」，「不应」不能拆成「应」；
「严重度」字段里出现错误 / 提示 / 待确认 就连一条「判定」，括号里的条件记在关系属性上。
```
✅ 累计实体 78、关系 140：用词 8、严重度 4（附录五的 3 个 + Q14 的「待确认」）；对应 8、用词 20、判定 25。Q05 的用词是「定义」，不连。

💡 最长匹配是个小坑。不按最长匹配，Q10 的「不宜」会同时连上「不宜」和「宜」，用词关系变成 21 条。图上看不出来，**数一下就能发现**，这就是验收数字的用处。

## 6 · 用地代码（选做）

```
最后加用地。从「适用」和「口径」里找用地代码（R、Rr、Rs4、C53、S51、Rr1–Rr4 这类写法），
统一归到中类（Rs4 → Rs，C53 → C5，S51 → S5），原始写法记在关系属性上；
「适用」里的叫「适用于」，「口径」里另外提到的叫「口径涉及」；Q03 口径里的 Rr3 只是举例，不算。
代码名称只能从 资料/质检智能体/上海控规质检_条文摘录.md 的「表3-2 用到的代码」里取，摘录没写的就空着，不许编。
中类再连到所属大类（归属大类）。口径里提到别的规则编号的（如 Q20 提到 Q12、Q18、Q19），连「口径引用」。
认不出的代码列出来并停止。
```
✅ 累计实体 **108**、关系 **213**：用地 30（其中 S6、S9、T、M1 没有名称）；适用于 25、口径涉及 27、归属大类 18、口径引用 3。

💡 「名称不许编」：S6、S9、T、M1 在摘录里没有名字，AI 很乐意替你补上，补得还像模像样，但那不是规则库给的。还有一个坑：口径里的 `Q12` 也长得像用地代码。

## 7 · 让图谱替你体检规则库

```
在 build_data.py 末尾加核对，每项打印「期望 / 实际」，没过的标出来：
① 每条规则的「原文」去掉空格和标点后，能不能在条文摘录对应的条文里逐字找到；找不到的，列出差在哪几个字；
② 每条规则「用词」对应的严重度，是不是都出现在它自己写的「严重度」里；
③ 有没有孤立节点。
核对结果也写进 data.js，网页上要显示。
```
✅ 逐字一致 15、近似 1（Q07：摘录多了「见附录二」）、原文为空 5；用词 → 严重度一致 20（Q05 无法核对）；孤立节点 0。

💡 把规则库变成实体和关系以后，交叉核对就成了数数和对照。注意 Q07 的「近似」：这一处没错，摘录多了个括号注；但「近似」本身不能直接当成通过——实操 4 就会看到为什么。

# C · 画出来（8–10）· 实操 2、3

## 8 · 骨架：把图画出来

```
写 apps/kg-cockpit/index.html，只读 ./data.js 和 ../../assets/echarts.min.js，不走 CDN。
1920×1080 设计稿等比缩放，深色风格和其它大屏一致。
左边：实体数 / 关系数 / 实体类型数 / 关系类型数 4 个数字，各类实体的个数，再下面是核对结果；
中间：关系图，各类实体一个颜色；右边先空着，下一句再做。
节点坐标在 build_data.py 里用力导向布局算好（固定随机种子），网页里 ECharts 的 layout 用 'none'。
```
✅ 左边显示 108 / 213 / 8 / 11；不带改动重跑 `build_data.py`，`data.js` 除生成时间外一字不差。

💡 为什么坐标要在 Python 里算：ECharts 的力导向每次打开都重新算，高亮一下整张图就抖；而且两个人看到的图不一样，「左上角那个点」没法沟通。

## 9 · 点一下：邻域和详情

```
点一个节点：它和 1 跳内的邻居保持高亮，其余变暗，视图自动移到这一片并放大；
右边显示它的全部属性，以及按「关系 + 方向」分组的邻居列表，点邻居就跳过去。
顶部加「邻域」下拉，可以切 1 跳 / 2 跳；再加一个搜索框，名称、编号、属性里的文字都能搜。
```
✅ 搜「4.3.2」→ 选中「准则2016 4.3.2」→ 右边能看到摘录原文和「← 依据 Q07」；切到 2 跳，Q07 的其它依据条文也亮起来。

💡 这就是 Yuxi 图谱页的三件套：搜实体、看属性、高亮关联子图。我们只用了一个 ECharts。

## 10 · 知识导图 + 直达链接

```
加第二页「导图」：规则库 → 类别 → 规则 → 依据 / 用词 / 判定 / 适用用地，默认展开到规则这一层，点了再往下展开。
再支持直达链接：打开 apps/kg-cockpit/#g=qc-rules&n=Q07 就直接选中 Q07；加 &v=tree 打开导图页。
```
✅ 导图第一层是 9 个类别加「明确不查的条文」；`#g=qc-rules&n=Q07` 打开就选中 Q07。

💡 这个链接就是和质检智能体的接口：智能体报「Q07 不通过」时附上它，人点一下就能看到依据条文和相关规则。

# D · 图谱体检（11）· 实操 4

## 11 · 从埋错版里找错

```
给 build_data.py 加一个 --rules 参数，可以换规则库文件（不传就用参考版）。
然后用 资料/知识图谱/规则库_埋错版.yaml 重跑。
里面埋了 6 处错。先让脚本能跑通，再用核对栏和图谱把剩下的找出来。
每找到一处，说清楚：哪条规则、错在哪、是哪一项核对（或者图上的什么地方）让你发现的。
不要拿它和参考版逐行比较。
```
```bash
python3 apps/kg-cockpit/build_data.py --rules 资料/知识图谱/规则库_埋错版.yaml
```
✅ 6 处全部找到，每一处都说得清是怎么发现的。答案在 `99_参考答案_做完再看.md`。练完不带参数再跑一次，换回参考版。

💡 两个看点：① 有一处，核对栏只给了个 ⚠「近似一致 0.98」——数字改了，相似度照样很高；② 有两处，任何自动核对都报不出来，只能靠人看图。**自动核对管得了格式，管不了意思。**

# E · 接 Yuxi（12）· 讲师演示

## 12 · 把 Yuxi 抽出来的图谱拉进来对照

讲师课前已经在 Yuxi 里，用同一份条文摘录建好了知识库并构建了图谱（见 `02_讲师准备.md`）。现场只跑三条命令：

```bash
python3 apps/kg-cockpit/fetch_yuxi.py --list
```

```bash
python3 apps/kg-cockpit/fetch_yuxi.py --kb-id <知识库ID> --max-nodes 300
```

```bash
python3 apps/kg-cockpit/build_data.py
```

刷新页面，右上角「图谱」里切换。

💡 两张图并排看三件事：① 准则 4.3.2 在 Yuxi 图里连着什么，有没有连到「轨道交通站点 300 米」；② 大模型有没有把「宜」当成「应」、把「不得」当成「不宜」；③ 有没有原文里根本没有的实体。
**大模型抽取的图谱是线索，不是依据。** 能当依据的，是人审定过的那张。
