# A · 数据准备（1–4）

## 1 · 先认识数据，别急着写

```
我要做一个静安区城市体检 WebGIS 平台。数据在 ../数据/01_成品数据层/。
先别写任何分析代码，帮我逐个文件看一眼：每个文件有多少行、有哪些列、
是什么坐标系（从数值范围和来源判断），然后列一张表告诉我
「哪些数据能支撑哪类分析」。
```
💡 先摸清家底再动手，这是全课第一条规矩。

## 2 · 统一坐标系（这一步不做，后面全白做）

```
这里有两类坐标：高德 POI 是 GCJ-02，OSM 的路网/设施是 WGS-84，
底图我要用高德。把所有数据统一转成 GCJ-02，
转完告诉我：各类点落在区界内的比例是多少。
```
💡 高德底图和 OSM 数据差约 **500 米**。不统一，后面所有覆盖率、生活圈都是错的，
**而且不会报错**——这是空间分析第一坑。

## 3 · 点和面要区别对待

```
刚才转完发现有些点跑到区界外了。帮我分情况处理：
· POI 这类"点"数据：界外的仍是真实设施，保留，让它参与"最近设施"计算；
· 人口栅格、建筑这类"面"数据：按区界重新裁剪，裁完再按七普常住人口重新标定总量。
处理完告诉我各自剩多少。
```
💡 一刀切裁掉会**低估覆盖率**——界外那家医院，对界内居民是真实可用的。

## 4 · 切网格 + 定归属

```
把静安切成 100 米网格（只保留落在区界内的），
再判断每个网格、每个 POI 分别属于 14 个街镇里的哪一个。
告诉我网格总数，和各街镇的网格数。
```
💡 网格化是空间分析最通用的套路：把"面"变成一堆可计算的小格子。

# B · 体检核心（5–9）

## 5 · 算覆盖率

```
写一个 build_data.py，把分析结果算完输出成 data.js（前端只负责画）。
先做第一件事：每个网格算到最近的医疗/教育/公园绿地/购物/交通的距离，
再按 300/500/800/1000 米四个半径，算出各类设施的覆盖率。
全区和 14 个街镇各算一份。
```
💡 分析在 Python 里算完、前端只读结果，这叫**前后端分离**。
不然网页里现算，一拖滑块就卡死。

## 6 · 合成健康评分

```
把医疗/教育/公园绿地/购物/交通这五类的 500 米覆盖率取平均，
作为"城市体检健康评分"。全区一个分，14 个街镇各一个分，按分数排序给我看。
```
💡 体检要有个总分。分数拉开差距，才有得讲。

## 7 · ⭐ 换个分母，结论就变了

```
上面那个覆盖率的分母是"网格数"，等于说没人住的地方缺医院也算盲区。
现在再算一版人口加权的：分母换成人口（用 静安_人口栅格100m.csv）。
两个口径都留在 data.js 里，让前端能切换。
算完告诉我：哪一类设施两种口径差得最多，为什么？
```
💡 **这是全课最值钱的一句**。静安的公园绿地按面积算 68%、按人口算只有 63%——
绿地都在人少的地方。汇报时必须说清你用的是哪个口径。

## 8 · 标出盲区

```
把"半径内没有该设施"的网格标出来当作盲区，四个半径都算，
输出成坐标点列表。告诉我医疗、教育、公园绿地各有多少个盲区网格，
以及哪个街镇的医疗盲区最多。
```
💡 覆盖率是个数字，**盲区是一张地图**——领导看得懂的是后者。

## 9 · 可达性时间场

```
再算一份可达性：每个网格到最近某类设施的距离，
按步行 80 米/分钟折算成分钟数。给医疗、教育、地铁、公园各算一份。
告诉我全区到最近医疗的中位步行时间。
```
💡 「覆盖了」和「走得到」是两件事。时间比距离更接近老百姓的感受。

# C · 空间分析（10–13）

## 10 · ⭐ 生活圈别画圆

```
加一个"15/30 分钟生活圈"：
用 静安_路网.geojson 建一个 networkx 图（边权 = 米距离），
从起点跑 dijkstra，cutoff = 分钟 × 步速（步行 80 米/分、骑行 250 米/分），
把可达的路网节点取凸包当作生活圈，并统计圈内各类公共服务数量。
起点先用 23 个地铁站 + 14 个街镇中心，全部预先算好存进 data.js。
```
💡 画个圆等于**假设人能穿墙**。真实的生活圈沿着路走，形状贴着街道、不规则——
这才是 WebGIS 和普通图表的区别。

## 11 · 用对比证明圆是错的

```
帮我做个对照：同一个起点，
分别用"1200 米直线缓冲圆"和"路网 15 分钟等时圈"，
算各自的面积和圈内设施数，差多少？差异来自哪里？
```
💡 这个对比一做，学员就再也不会用缓冲圆糊弄了。

## 12 · 选址分析

```
加"选址推荐"：用餐饮 POI，用户选一个品类，
在网格上算：需求（周边所有餐饮数）− 竞争（该品类已有数）= 适宜度，
高分就是蓝海。标出 Top8 推荐点。
影响半径做成可调的：150/300/450/600 米各算一份。
```
💡 适宜度 = **人气 − 竞争**。有人流、但同品类还少的地方最值得开店。

## 13 · ⭐ 商圈聚类 + 参数敏感性

```
加"商圈识别"：对 6275 家餐饮做 DBSCAN 聚类，画出每个商圈的凸包范围。
注意：eps 必须用米坐标，不能直接拿经纬度。
把 eps（80–300 米）和最小门店数（10–60）做成多组参数都预先算好，
让前端能拉滑块实时切换。最后告诉我：参数变化时商圈数量怎么变？
```
💡 **eps 80 米/最小 10 家 → 120 个商圈；eps 300 米/最小 60 家 → 11 个**。
同一批数据，参数一调差 10 倍——**聚类没有唯一正确答案**，这是讲聚类最好的素材。

# D · 做成大屏（14–18）

## 14 · 先搭空壳骨架

```
现在做前端 index.html，风格和上午的交通数智平台一致：
· 1920×1080 设计稿，窗口变化时整体等比缩放
· 顶栏：标题 + 全局筛选（街镇/设施/服务半径/口径）+ 右上角健康评分
· 左侧竖排 Tab：体检总览 / 人口画像 / 公服覆盖 / 生活圈 / 可达性 / 商业分析
· 内容区先只放四个空的指标卡
数据从 data.js 读，用本地 echarts.min.js，不要联网。
```
💡 一次要八页，AI 一定给你一堆错位的东西。**先把版式定死**，内容留空。

## 15 · 地图居中做主图

```
"体检总览"页改成 12 列栅格：
顶部四个 KPI 卡各占 3 列；中间 6 列整块给地图，跨 3 行做主视觉；
两侧各 3 列放辅助图。地图上叠：街镇边界 + 各类设施点（按类别着色）。
```
💡 大屏的第一眼决定气质。**地图跨行做主视觉**，这一条就把"网页"变成了"大屏"。

## 16 · 一次加一页

```
"公服覆盖"页：中间地图画盲区红点，右侧放街镇覆盖率排名、
半径—覆盖率曲线、五类设施对比。顶栏切设施类型和半径时，整页联动。
```
```
"生活圈"页：中间画等时圈多边形，左侧列出起点（可点击切换），
右侧放圈内服务结构、15 vs 30 分钟对比、步行 vs 骑行面积对比。
```
```
"商业分析"页：左侧做三个图层切换（商圈识别 / 选址推荐 / 餐饮热力），
每个图层配自己的参数滑块，右侧放排名和参数敏感性曲线。
```
💡 **一次加一页，加完刷新看一眼**。错了当场知道是哪页——这是全课最省时间的习惯。

## 17 · 点击下钻

```
加街镇下钻：点地图上的街镇、或点排名里的任意一条，
都进入该街镇的详情页：五类覆盖率雷达（该街镇 vs 全区）、
设施构成、关键指标、半径曲线、可达性、与全区对比。
右上角"返回"回到原页面。
```
💡 能点进去看细节，平台才算"能用"。

## 18 · ⭐ 收敛成一句话

```
最后做一张"结论卡"：把四个来源的证据串起来——
① 空间体检（医疗覆盖率、最短板街镇）
② 人口口径（人口加权结果 + 老龄化比例）
③ 职住结构（静安是就业型还是居住型）
④ 民意数据（12345 诉求结构）
最后给出一句能直接写进汇报的结论。
```
💡 八个页面不是八个结论。**把多个证据串成一句判断**，这份分析才算做完——
这是"分析师"和"做图的"的区别。

# 卡住了怎么办

**报错别慌**，整段复制给 AI，加一句：
```
报错原文：<粘贴>
请先解释原因，再给最小修复，不要重写整个文件。
```

**结果不对**，别推倒重来：
```
<某张图>显示不对，现象是 ____。
请先定位是数据筛选、聚合口径还是图表配置的问题，
只改相关部分，并用一句话说明你改了什么。
```

**实在做不动**，看 `../讲师版参考/`（`build_data.py` + `index.html` 是完整答案）——
但先自己写 10 分钟再看。

# 三个不报错、但结果全错的坑

| 坑 | 现象 | 怎么防 |
|---|---|---|
| **坐标系不统一** | 点整体偏移 500 米，图看着还挺正常 | 转换后检查点落界内比例，应≈100% |
| **DBSCAN 用经纬度** | 聚类结果莫名其妙 | eps 必须用**米坐标**，1 度经度≈95 km |
| **抽样当全量** | 算出"占比 193%" | 画图可以抽样，**算占比必须用全量** |
