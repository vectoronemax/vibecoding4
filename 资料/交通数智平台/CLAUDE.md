# 交通数智平台

> 把这个文件复制到你的项目根目录。Claude Code 每次会话都会自动读它。
> 它的作用是：**把课上反复强调的口径与约定固化下来，不用每次在 prompt 里重复。**

## 项目是什么

纯前端数据大屏，无后端、无数据库、无地图 API Key。一个文件夹，起 http server 就能跑。

```
apps/commute/   全国主要城市通勤监测（45城 × 9指标 × 2022-2024）
apps/metro/     上海轨道交通客流监测（302站 × 2017年5-8月）
data/           只读数据源，任何情况下不得修改或覆盖
assets/         echarts.min.js + china.js + shanghai.js，本地引用不走 CDN
```

## 技术约定

- **前后端分离**：Python 脚本 `build_dashboard_data.py` 读 `data/` 里的 CSV，产出 `data.js`（`window.XX_DATA`）；
  `index.html` 只读 `data.js`，**换数据只需重跑脚本，网页代码一行都不用改**。
- 单文件 HTML + 原生 JS + ECharts 5，不引框架、不上构建工具。
- 深色科技风：底色 `#050d22`，主色青 `#2ee6ff`，辅色 `#5fe3a1` / `#7c9cff` / `#ffc14d`。
- 设计稿 1920×1080，16:9 等比缩放适配，不做响应式重排。
- `data.js` 用**下标压缩**：城市 / 指标 / 年份都用数组下标引用，不重复写字符串。
- 所有图表实例存进一个全局 `charts` 对象，便于统一 resize 和销毁。

## 🔴 口径红线（违反即为错，不是风格问题）

1. **跨城汇总必须声明口径。** 报告的「总体平均」是**人口加权**，「分规模平均」是**算术平均**。
   直接对 45 城取算术平均，45分钟指标虚高 2.53pp。默认用人口加权，并在图上注明。
2. **指标有方向**，见 `data/commute/07_指标字典.csv` 的「指标方向」列：
   `+1` 越大越好 / `-1` 越小越好 / `0` 中性。
   配色和排名必须方向感知；**`通勤空间半径` 方向为 0，不得参与"谁更好"的排名与综合指数**。
3. **缺失不是 0。** 空值不参与排名、不参与均值、不填 0、不 `fillna(0)`。
   海口 / 银川 / 西宁无轨道数据；长表 1157 行而非 1215 行是正常的。
4. **轨道客流全部是日均**（工作日 87 天 / 非工作日 36 天平均），不是区间总量，图例和轴标题必须写"日均"。
5. **轨道数据是 2017 年 5–8 月**，只用 2017 年在运营的线路（1–13 号线 + 16 号线）。
   14 / 15 / 17 / 18 号线当时未开通，用现网线路会造成时代错置。
6. 45 城几何是**市域**边界，通勤指标口径是**中心城建成区**，两者不可直接比较，相关图表标题要标注。

## 工作方式

- **一次只加一个功能。** 加完我刷新看一眼，确认了再继续下一个。不要一次给我十张图。
- **每一步都要给可证伪的验收标准**：行数是多少、和哪个已知数字对得上、怎么算就能反算回去。
  说"应该没问题"不算验收。
- 涉及**筛选、聚合、匹配**的地方，一律报告命中率与丢弃条数，**不许静默丢数据**。
- 改错时先定位是数据筛选、聚合口径还是图表配置的问题，**只改相关部分**，
  并用一句话说明改了什么、为什么。不要推倒重来。
- `data/` 目录只读。所有产物写到 `apps/*/`。
